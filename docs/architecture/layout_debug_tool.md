# Справка по `layout_debug_tool.py`

## Назначение

[tools/layout_debug_tool.py](C:/Users/Zver/Documents/Codex/2026-04-26/pygame-python/tools/layout_debug_tool.py) — это отдельная графическая утилита для тонкой настройки интерфейса проекта `Durak`.

Она нужна для:

- выбора визуального объекта;
- изменения его позиции;
- изменения его размеров;
- сохранения изменений в постоянный конфиг проекта;
- хранения текстовых задач по объекту через `TO DO LIST`.

## Что утилита должна уметь в текущей архитектуре

Утилита строится поверх финальной схемы интерфейса проекта:

- игровая сцена рисуется через `pygame`;
- интерфейсный слой собран на `pygame_gui`.

Поэтому утилита должна работать с тремя типами экранов:

- `Игровой стол`
- `Стартовое окно`
- `Финальное окно`

Для выбранного режима она должна:

- показывать экран как превью;
- накладывать поверх редактируемые объекты;
- позволять выбрать объект мышью или из списка;
- показывать его параметры;
- менять:
  - `delta_x`
  - `delta_y`
  - `width_delta`
  - `height_delta`
- сохранять и очищать `TO DO LIST`;
- записывать изменения в `app_config.json`.

## Главная структура файла

### `LayoutDebugTool`

Основной класс утилиты. Он управляет:

- запуском окна;
- загрузкой `DurakApp`;
- режимами превью;
- выбором объекта;
- изменением параметров;
- отрисовкой интерфейса утилиты;
- сохранением состояния.

## Основные блоки логики

### 1. Настройка превью

Методы:

- `configure_preview_for_window()`
- `_prepare_endgame_preview()`
- `sync_preview_ui()`

Они:

- переключают утилиту между игровым столом и модалками;
- подготавливают тестовое состояние;
- обновляют UI перед показом превью.

### 2. Работа с конфигом

Методы:

- `restore_session_defaults()`
- `apply_changes()`

Они:

- откатывают изменения текущей сессии;
- сохраняют изменения в постоянный конфиг.

### 3. Работа с объектами

Методы:

- `current_objects()`
- `ordered_object_items()`
- `object_hit_order()`
- `selected_object()`
- `select_object()`

Они:

- собирают список доступных объектов;
- выбирают активный объект;
- подготавливают данные для списка и overlay.

### 4. Изменение layout

Методы:

- `move_selected_block()`
- `resize_selected_block()`

Они:

- меняют смещения объекта;
- меняют дельты размеров объекта.

### 5. TO DO LIST

Методы:

- `save_todo()`
- `clear_todo()`

Они:

- сохраняют текстовую инструкцию в конфиг;
- очищают задачу для выбранного объекта.

### 6. Обработка ввода

Методы:

- `handle_click()`
- `handle_control_action()`
- `handle_key()`

Они:

- обрабатывают мышь;
- обрабатывают кнопки управления;
- принимают ввод в поле шага и в `TO DO LIST`.

### 7. Отрисовка

Методы:

- `render_preview()`
- `render_object_overlays()`
- `render_toolbar()`
- `render_panels()`

Они:

- рисуют превью сцены;
- накладывают выделения объектов;
- рисуют верхнюю панель режимов;
- рисуют список объектов, инспектор и `TO DO LIST`.

## Что хранится по объекту

Для каждого объекта утилита работает с такими полями:

- `delta_x`
- `delta_y`
- `width_delta`
- `height_delta`
- `todo_text`
- `module`
- `type`
- `label`

## Текущее состояние

Архитектурно утилита уже должна опираться на финальную схему проекта:

- `game_table.py` владеет только сценой;
- `gui_layer.py` владеет всем игровым интерфейсом на `pygame_gui`;
- `modals.py` владеет модальными окнами;
- `menu.py` владеет главным меню;
- `config.py` и `app_config.json` владеют постоянной конфигурацией layout.

Следующий критерий качества для утилиты — не архитектурная совместимость, а удобство реальной тонкой настройки интерфейса.
