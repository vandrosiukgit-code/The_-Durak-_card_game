# Архитектура интерфейса

Этот документ описывает текущую архитектуру интерфейса проекта `Durak`: распределение ответственности между `pygame`, `pygame_gui`, layout-конфигурацией и отладочными инструментами.

## 1. Общий принцип

Интерфейс проекта разделён на два слоя:

- `pygame` отвечает за сцену и визуальную часть игрового стола;
- `pygame_gui` отвечает за интерактивные GUI-элементы.

На практике это означает:

- стол, карты, колода, козырь, портреты игроков и анимации карт рисуются через `pygame`;
- панели, кнопки, модальные окна, интерактивные элементы меню и вспомогательные GUI-компоненты работают через `pygame_gui`.

Такой подход позволяет сохранять точный контроль над карточным интерфейсом, но не дублировать разные системы обработки кликов и состояний.

## 2. Роль основных UI-модулей

### [durak_app/app.py](C:/Users/Zver/Documents/Codex/2026-04-26/pygame-python/durak_app/app.py)

Главный координатор интерфейса. Отвечает за:

- создание окна `pygame`;
- запуск общего цикла `process_events -> update -> draw`;
- переключение между меню, игровым столом и модальными окнами;
- связывание GUI-слоя с игровым состоянием.

`app.py` не должен детально рисовать кнопки, панели или модалки. Его задача — управлять состояниями экранов и передавать данные в нужные UI-модули.

### [durak_app/game_table.py](C:/Users/Zver/Documents/Codex/2026-04-26/pygame-python/durak_app/game_table.py)

Отвечает за визуальный слой игрового стола:

- сукно;
- зоны игроков;
- карты в руках;
- карты на столе;
- колоду и козырь;
- подписи игроков;
- счёт поражений.

Этот модуль не должен владеть интерактивными GUI-кнопками или модальными окнами.

### [durak_app/gui_layer.py](C:/Users/Zver/Documents/Codex/2026-04-26/pygame-python/durak_app/gui_layer.py)

Центральная точка интеграции `pygame_gui`.

Отвечает за:

- создание и хранение `UIManager`;
- панель `Actions`;
- игровые кнопки `Pass`, `Take`, `Restart`, `Surrender`;
- обновление видимости и доступности GUI-элементов;
- маршрутизацию событий `pygame_gui` обратно в приложение;
- подключение модалок из `modals.py`.

Именно этот модуль считается владельцем жизненного цикла GUI.

### [durak_app/menu.py](C:/Users/Zver/Documents/Codex/2026-04-26/pygame-python/durak_app/menu.py)

Отвечает за экран главного меню.

На текущем этапе меню уже не использует старую схему с невидимыми hotspot-кнопками как основную модель. Теперь:

- структура меню собрана из `pygame_gui`-панелей;
- настройки представлены через `UIButton`, `UILabel`, `UIImage`, `UIPanel`;
- dropdown выбора колоды и overlay выбора ассетов тоже живут в `pygame_gui`;
- `pygame` в меню используется только как фон экрана, а не как основной способ собирать интерактивный интерфейс.

Это уже постоянная архитектура меню, а не временный переходный слой.

### [durak_app/modals.py](C:/Users/Zver/Documents/Codex/2026-04-26/pygame-python/durak_app/modals.py)

Отвечает за сборку модальных окон целиком на `pygame_gui`.

Сейчас это:

- стартовое модальное окно;
- финальное модальное окно;
- overlay;
- panel;
- labels;
- кнопки действий.

`modals.py` не рисует окна вручную через `pygame.draw`. Его задача — собирать модальные UI-компоненты и обновлять их содержимое.

### [durak_app/ui.py](C:/Users/Zver/Documents/Codex/2026-04-26/pygame-python/durak_app/ui.py)

Содержит низкоуровневые UI-утилиты старого слоя. На текущем этапе отсюда по-прежнему важны анимации карт.

## 3. Обработка событий

Цель проекта — свести всю интерактивность интерфейса к одной системе событий `pygame_gui`.

Сейчас это уже верно для:

- панели `Actions`;
- модальных окон;
- главного меню.

Исключение остаётся только для кликов по самим игровым картам на столе и в руке игрока. Это нормальное исключение, потому что карты являются частью игровой сцены, а не GUI-панелями.

Текущий принцип работы событий:

- GUI-события обрабатываются через `pygame_gui.UI_BUTTON_PRESSED` и `UIManager`;
- игровые клики по картам обрабатываются отдельно, только если курсор не попал в GUI.

## 4. Layout и базовые блоки интерфейса

В проекте введено понятие базового блока интерфейса.

Базовый блок — это крупный редактируемый UI-элемент, например:

- панель игрока;
- панель `Actions`;
- блок меню;
- кнопка;
- подпанель настроек.

Каждый экран объявляет свои базовые блоки сам через `layout_schema()`.

Примеры:

- `game_table.py` объявляет блоки игрового стола;
- `menu.py` объявляет блоки меню.

## 5. Постоянная layout-конфигурация

### [app_config.json](C:/Users/Zver/Documents/Codex/2026-04-26/pygame-python/app_config.json)

Файл хранит постоянные настройки интерфейса.

Для layout сейчас особенно важен раздел:

- `layout`

В нём хранятся `delta_x` и `delta_y` для базовых блоков интерфейса.

Принцип такой:

- код экрана задаёт базовое положение блока;
- `app_config.json` хранит корректирующее смещение;
- это позволяет подгонять интерфейс без ручного редактирования координат в коде.

### [durak_app/config.py](C:/Users/Zver/Documents/Codex/2026-04-26/pygame-python/durak_app/config.py)

`AppConfig` отвечает за:

- загрузку `app_config.json`;
- сохранение изменений;
- синхронизацию структуры layout с актуальным кодом экранов.

Это позволяет проекту переживать изменения состава экранов и базовых блоков без ручной пересборки конфига.

## 6. Отладка layout

### [tools/layout_debug_tool.py](C:/Users/Zver/Documents/Codex/2026-04-26/pygame-python/tools/layout_debug_tool.py)

Это отдельная графическая утилита разработки.

Она:

- запускается вне основной игры;
- показывает выбранный экран как картинку;
- накрывает базовые блоки полупрозрачными прямоугольниками;
- позволяет выбрать блок;
- двигает его через изменение `delta_x` и `delta_y`;
- сохраняет изменения в `app_config.json`.

Принципиально важно:

- утилита работает только с постоянной конфигурацией;
- она не зависит от состояния конкретной игровой партии.

## 7. Тема `pygame_gui`

### [ui_theme/theme.json](C:/Users/Zver/Documents/Codex/2026-04-26/pygame-python/ui_theme/theme.json)

Тема определяет единый визуальный стиль интерактивных GUI-элементов:

- панелей;
- кнопок;
- текста;
- модалок;
- элементов меню;
- overlay и dropdown-компонентов.

Theme-файл не хранит layout или игровые координаты. Он отвечает только за внешний вид элементов `pygame_gui`.

## 8. Целевая ответственность UI-слоя

На текущем этапе и в дальнейшей архитектуре мы придерживаемся такого распределения:

- `app.py` — состояние экранов и общая оркестрация;
- `game_table.py` — только отрисовка стола;
- `menu.py` — экран меню на `pygame_gui`;
- `modals.py` — сборка модалок на `pygame_gui`;
- `gui_layer.py` — жизненный цикл `pygame_gui`, игровые кнопки и маршрутизация событий;
- `config.py` + `app_config.json` — постоянная интерфейсная конфигурация;
- `layout_debug_tool.py` — внешняя утилита настройки layout.
