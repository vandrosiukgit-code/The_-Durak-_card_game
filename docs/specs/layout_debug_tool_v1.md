# Layout Debug Tool v1

## Финальная спецификация для проекта `Durak`

## 1. Назначение

`layout_debug_tool.py` — это отдельная графическая утилита разработки для тонкой настройки интерфейса проекта `Durak`.

Цель утилиты:

- редактировать положение и размеры визуальных объектов без ручного изменения кода;
- работать с постоянной layout-конфигурацией проекта;
- упрощать подготовку точных задач для ИИ через встроенный `TO DO LIST`.

Утилита **не является частью игрового приложения для пользователя** и запускается отдельно.

## 2. Соответствие текущей архитектуре

Утилита должна учитывать, что проект использует два уровня интерфейса:

1. `pygame` — игровая сцена:
- сукно
- зоны игроков
- карты
- колода
- козырь
- портреты

2. `pygame_gui` — интерфейсный слой:
- кнопки
- панели
- подписи
- счётчики
- модальные окна
- главное меню

Следовательно, утилита должна уметь работать:
- и со сценическими объектами;
- и с GUI-объектами.

## 3. Принцип работы

Утилита запускается отдельно от игры и работает с временной копией конфигурации в памяти.

Пользователь:
1. выбирает экран;
2. видит превью интерфейса;
3. выбирает объект;
4. изменяет его положение и размер;
5. при необходимости добавляет текстовую задачу;
6. сохраняет изменения в постоянный конфиг только по явной команде.

## 4. Поддерживаемые экраны v1

Первая версия должна работать со следующими экранами:

1. `Игровой стол`
2. `Главное меню`
3. `Стартовое модальное окно`
4. `Финальное модальное окно`

## 6. Основная модель данных объекта

Каждый редактируемый объект должен иметь минимум такие поля:

- `object_id`
- `screen_id`
- `module_path`
- `object_type`
- `label`
- `base_rect`
- `delta_x`
- `delta_y`
- `width_delta`
- `height_delta`
- `todo_text`

### Пояснение
- `base_rect` — базовая геометрия из кода
- `delta_x`, `delta_y` — смещения относительно базы
- `width_delta`, `height_delta` — корректировка размеров относительно базы

Важно: утилита работает не с “произвольным rect”, а с **layout-дельтами**, совместимыми с архитектурой проекта.

## 7. Источник данных

Источник истины:
- экранные `layout_schema()`
- связанная геометрия из экранов и GUI-слоя
- [app_config.json](C:/Users/Zver/Documents/Codex/2026-04-26/pygame-python/app_config.json)

Утилита не должна полагаться только на рекурсивный обход `pygame_gui`, потому что часть объектов проекта находится в сцене `pygame`.

Правильная модель:
- `schema-first`
- плюс привязка к реальным живым GUI-объектам, где это применимо

## 8. UI утилиты

### 8.1. Верхняя панель
Содержит:
- выбор экрана;
- статус текущего режима;
- индикатор наличия несохранённых изменений.

### 8.2. Центральная область
Показывает превью выбранного экрана.

Поверх превью:
- полупрозрачные прямоугольники объектов;
- подсветка выбранного объекта;
- краткая подпись объекта;
- его текущие глобальные координаты.

### 8.3. Навигатор объектов
Отдельная панель со списком или деревом объектов.

Требования:
- список формируется автоматически из схемы текущего экрана;
- выбранный объект в списке должен автоматически синхронизироваться с выбранным объектом на превью;
- при выборе мышью на превью навигатор должен автоматически подсветить этот объект в списке.

### 8.4. Инспектор объекта
Для выбранного объекта показываются:
- `object_id`
- `label`
- `screen_id`
- `module_path`
- `object_type`
- текущий `x, y`
- текущий `width, height`
- текущие `delta_x, delta_y, width_delta, height_delta`

### 8.5. Панель управления
Должна позволять:
- двигать объект вверх/вниз/влево/вправо;
- изменять ширину;
- изменять высоту;
- задавать шаг изменения в пикселях.

## 9. Управление

### 9.1. Выбор объекта
Поддержать:
- выбор ЛКМ по overlay;
- выбор из списка объектов.

### 9.2. Перемещение
Поддержать управление с клавиатуры:
- стрелки — изменение `delta_x/delta_y`

### 9.3. Изменение размеров
Поддержать отдельные команды:
- увеличить/уменьшить ширину;
- увеличить/уменьшить высоту.

### 9.4. Шаг редактирования
Поле ввода шага:
- только целое число;
- значение по умолчанию — `1`;
- должно валидироваться.

## 10. TO DO LIST

### 10.1. Назначение
Каждому объекту можно привязать текстовую задачу на естественном языке.

Примеры:
- `Поднять выше`
- `Сместить ближе к колоде`
- `Уменьшить ширину`
- `Выровнять по левому краю панели`

### 10.2. Хранение
Для каждого объекта сохраняется:
- `todo_text`

Этого достаточно для v1.

### 10.3. Действия
Нужны:
- `Save TO DO`
- `Clear TO DO`

`Clear TO DO` должен:
- очищать задачу в памяти;
- очищать поле ввода;
- удалять задачу из сохранённого состояния после `Apply`.

## 11. Изоляция состояния

Утилита должна использовать **временную копию конфигурации в памяти**.

Принцип:
- любые изменения сначала живут только в RAM;
- основной конфиг не меняется до команды `Apply`;
- можно безопасно экспериментировать без риска испортить layout.

Это обязательное свойство v1.

## 12. Сохранение

### 12.1. Apply
Кнопка `Apply`:
- переносит изменения из временного состояния в постоянный конфиг;
- записывает данные в [app_config.json](C:/Users/Zver/Documents/Codex/2026-04-26/pygame-python/app_config.json)

### 12.2. Atomic Write
Сохранение должно быть атомарным:
1. запись во временный файл
2. `os.replace(...)`

Это нужно для защиты от порчи конфига.

## 13. Откат

Нужна кнопка:
- `Reset session`

Она должна:
- откатывать все изменения текущей сессии утилиты;
- не менять уже сохранённый конфиг;
- восстанавливать состояние на момент запуска утилиты.

## 14. Что не входит в v1

Следующие функции полезны, но откладываются:
- `Undo/Redo`
- grid overlay
- snapshot testing
- встроенный запуск из основной игры
- singleton-архитектура
- `toggle_debug_mode()` внутри `DurakApp`

## 15. Архитектурные ограничения

### Не делать в v1
- не делать утилиту частью игрового окна;
- не завязывать её только на `pygame_gui`;
- не пытаться редактировать layout через прямую перезапись кода модулей.

### Делать в v1
- работать через схемы экранов;
- работать через layout-дельты;
- использовать единый конфиг;
- разделять сцену и GUI.

## 16. Критерии готовности v1

Версия считается готовой, если:
1. утилита запускается отдельно;
2. поддерживает 4 экрана:
   - игровой стол
   - главное меню
   - стартовую модалку
   - финальную модалку
3. умеет выбирать объекты мышью и из списка;
4. умеет менять положение и размеры;
5. умеет работать с шагом в пикселях;
6. умеет сохранять `TO DO`;
7. умеет очищать `TO DO`;
8. умеет применять изменения в `app_config.json`;
9. умеет откатывать изменения текущей сессии.
