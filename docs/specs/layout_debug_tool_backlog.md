# Layout Debug Tool v2: рабочий backlog

## Главный принцип

Сначала собираем полноценный shell интерфейса на `pygame_gui` в стиле Windows 95.

Часть блоков может временно работать на заглушках.  
Главная цель первого этапа — получить удобное рабочее место, где всё находится под рукой и визуально не смешивается с игрой.

Актуальная спека: [layout_debug_tool_v2.md](layout_debug_tool_v2.md)

## Этап 4. Навигатор объектов

Навигатор не является фильтром.

Основная задача:
- показывать путь к выбранному объекту от родителя к child-объекту.

Минимум:
- при выборе объекта в Preview Area навигатор показывает его путь;
- текущий объект выделен;
- путь читается человеком без открытия JSON.

Пример:

```text
game_table
`- players
   `- left
      `- panel
         |- portrait
         |- name_label <
         |- role_label
         `- loss_label
```

Позже:

- добавить переход по клику в дереве.

## Этап 5. Инспектор

Инспектор показывает и редактирует выбранный объект.

Поля:
- `object_id`;
- `label`;
- `screen_id`;
- `module_path`;
- `object_type`;
- `x`, `y`;
- `width`, `height`;
- `delta_x`, `delta_y`;
- `width_delta`, `height_delta`.

Кнопки:
- `Dismiss`;
- `Cancel`;
- `Copy id`.

Семантика:
- `Dismiss` принимает изменения формы инспектора в RAM-сессию и обновляет preview;
- `Cancel` откатывает локальные изменения текущего объекта;
- `Copy id` копирует id объекта;
- инспектор не пишет напрямую в `app_config.json`.

## Этап 6. Управление объектом

Все манипуляции положением и размером выполняются только в панели `УПРАВЛЕНИЕ ОБЪЕКТОМ`.

Нужно:
- поле `Step`;
- кнопки Move: left/up/down/right;
- кнопки Size: `-W`, `+W`, `-H`, `+H`;
- клавиатурные стрелки дублируют Move;
- используется текущий `Step`;
- если объект не выбран, controls disabled.

В Preview Area запрещены:
- drag;
- resize;
- handles.

## Этап 7. TO DO как навигация по задачам

TO DO — не просто поле, а отдельная навигационная система.

Источник:
- RAM-сессия;
- после `Apply`: `app_config.json`;
- путь: `layout.<screen_id>.<object_id>.todo_text`.

Панель:

1. `СПИСОК ЗАДАЧ`
   - все объекты с непустым `todo_text`;
   - screen_id;
   - object_id;
   - label;
   - короткий preview задачи;
   - changed/unsaved marker.

2. `ЗАДАЧА ВЫБРАННОГО ОБЪЕКТА`
   - текущий объект;
   - многострочное поле `todo_text`;
   - `Save TO DO`;
   - `Clear TO DO`;
   - `Go to obj`;
   - `Copy task`.

Клик по задаче:
- переключает экран;
- выбирает объект;
- обновляет preview;
- обновляет навигатор;
- обновляет инспектор;
- показывает задачу справа.

## Этап 8. Copy task

Добавить кнопку `Copy task`.

Она копирует в буфер обмена структурированный текст, не JSON.

Формат:

```text
Layout task:
- screen_id: game_table
- object_id: player_left_panel
- label: Левая панель игрока
- object_type: player_panel
- module_path: durak_app.game_table
- rect: x=32, y=180, w=170, h=620
- deltas: dx=0, dy=0, dw=0, dh=0
- todo: Поднять панель выше и выровнять относительно верхней панели игрока.
```

Правила:
- если выбрана TO DO запись, копируется она;
- если TO DO запись не выбрана, копируется текущий выбранный объект;
- если задача пустая, поле `todo` остаётся в тексте.

## Этап 9. Apply и Reset

1. `Apply`:
   - сохраняет всю RAM-сессию в `app_config.json`;
   - использует атомарную запись;
   - показывает понятный статус;
   - не требует ручной проверки JSON.

2. `Reset session`:
   - откатывает всю RAM-сессию к состоянию запуска утилиты;
   - обновляет preview;
   - обновляет навигатор;
   - обновляет инспектор;
   - обновляет TO DO.
