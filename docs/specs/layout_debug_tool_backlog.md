# Layout Debug Tool v2: рабочий backlog

Статус: закрыт как рабочий backlog v2, 2026-05-17.

Этот backlog фиксирует путь от стабильного shell-каркаса к первой живой версии Layout Debug Tool v2. Дальше новые задачи оформляются отдельным backlog, чтобы не смешивать закрытую рабочую точку и будущую полировку.

## Главный принцип

Shell-интерфейс утилиты строится на `pygame_gui` в стиле Windows 95/98.

Ручная pygame-отрисовка допускается только внутри `PREVIEW AREA`, потому что там имитируется игровой экран. Shell-элементы, панели, кнопки, поля, списки и scrollbars должны быть `pygame_gui`-элементами.

## Рабочая точка

Файл реализации:
- `tools/layout_debug_tool_v2_shell.py`

Тема:
- `ui_theme/layout_debug_tool_win95.json`

Текущее состояние:
- shell-прототип существует отдельно от старой утилиты;
- старый файл `tools/layout_debug_tool.py` не используется как основа v2;
- интерфейс визуально отделён от игры стилем Windows 95/98;
- ручные shell-scrollbars и ручные shell-frame overlays убраны;
- ручная отрисовка осталась только внутри `PREVIEW AREA`;
- окно адаптировано под рабочий экран пользователя `1680 x 1050` и использует размер `1600 x 940`.

## Закрытые этапы

1. Shell-каркас на `pygame_gui`.

2. Windows 95/98 оформление shell-интерфейса.

3. Актуальная карта экрана в отдельном документе.

4. Слой загрузки layout-данных из `app_config.json`.

5. Внутренняя модель layout-объекта.

6. Переключение экранов:
   - `game_table`;
   - `main_menu`;
   - `modal_intro`;
   - `modal_endgame`.

7. Навигатор объектов, обновляющийся при смене экрана и выборе объекта.

8. `PREVIEW AREA` с canvas `1600 x 900`, aspect ratio `16:9`, hover и select.

9. Инспектор выбранного объекта через безопасную property-схему:
   - `x`;
   - `y`;
   - `width`;
   - `height`;
   - `delta_x`;
   - `delta_y`;
   - `width_delta`;
   - `height_delta`;
   - `color`;
   - `font`;
   - `font_size`.

10. Управление объектом:
    - кнопки Move;
    - кнопки Size;
    - поле `Step`;
    - стрелки клавиатуры дублируют Move.

11. RAM-сессия изменений:
    - изменения живут в памяти до `Apply`;
    - `Dismiss` принимает состояние выбранного объекта в текущую RAM-точку;
    - `Cancel` откатывает выбранный объект к snapshot;
    - `Reset session` откатывает всю RAM-сессию;
    - статус показывает `saved` / `UNSAVED`.

12. `Apply`:
    - сохраняет RAM-layout в `app_config.json`;
    - сохраняет остальные разделы конфига;
    - пишет через временный файл и атомарную замену.

13. `TO DO`:
    - список созданных задач берётся из `layout.<screen>.<object>.todo_text`;
    - можно создать новую задачу для выбранного объекта;
    - `Clean` очищает поле создания;
    - выбранная задача отображается в просмотрщике;
    - `Copy` копирует в буфер обмена структурированный текст для чата, не JSON.

## Принятые ограничения v2

- `PREVIEW AREA` используется только для hover/select.
- Drag/resize мышью в preview запрещены.
- Основное редактирование идёт через инспектор и блок `CONTROL`.
- Shell не должен смешиваться визуально с игрой.
- Пользователь не обязан читать `app_config.json`, чтобы понять результат обычных действий.
