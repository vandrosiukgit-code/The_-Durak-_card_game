# Layout Debug Tool v2

## Финальная UI-спецификация для следующего этапа

## 1. Назначение

`layout_debug_tool.py` — отдельная графическая утилита разработки для настройки layout проекта `Durak`.

Версия v2 фиксирует главный приоритет: сначала собрать удобный интерфейс утилиты на `pygame_gui`, затем подключать живые данные и поведение.

Утилита должна:
- визуально отделяться от игры;
- не требовать ручного чтения `app_config.json`;
- помогать выбирать, настраивать и документировать layout-объекты;
- готовить структурированные задачи для передачи в чат ИИ.

## 2. Визуальный стиль

Интерфейс утилиты оформляется в стиле Windows 95.

Цель стиля:
- визуально не смешивать игру и инструмент;
- подчеркнуть, что это техническая dev-утилита;
- использовать понятные панели, кнопки, поля, чекбоксы, статусную строку и меню.

Игровое превью остаётся настоящим экраном игры.  
Все панели утилиты должны быть `pygame_gui` shell-интерфейсом вокруг превью.

## 4. Основные зоны интерфейса

### 4.1. Верхнее окно и меню

Верхняя часть имитирует техническое приложение Windows 95:
- title bar;
- menu bar;
- toolbar/status row.

Минимальные команды:
- выбор экрана;
- `Apply`;
- `Reset session`;
- статус сессии: `saved`, `UNSAVED`, `APPLIED`, `ERROR`.

`Apply` и `Reset session` работают на уровне всей RAM-сессии.

### 4.2. Фильтр

Фильтр — отдельная горизонтальная зона под выбором экрана.

Назначение:
- определить, какие объекты доступны для hover/select;
- скрыть служебный шум;
- быстро показать изменённые объекты и объекты с задачами.

Минимальные фильтры:
- `visible`;
- объектные типы: `panel`, `button`, `label`, `card_zone`, `player_panel`, `hand_zone`, etc.;
- `helper`;
- `changed`;
- `TODO`;
- `Show hitboxes`.

`All` может быть реализован как сброс выбранных типовых фильтров.

### 4.3. Preview Area

`PREVIEW AREA` — только область просмотра и выбора.

Правила:
- источник: game canvas `1600 x 900`;
- aspect ratio: `16:9`;
- viewport всегда сохраняет пропорции;
- экран игры вписывается в доступную область без искажения;
- layout-объекты живут в координатах игры `1600 x 900`;
- preview только масштабирует отображение.

Поведение:
- hover мышью подсвечивает объект;
- ЛКМ выбирает объект;
- selected-объект получает тонкую рамку;
- drag/drop запрещён;
- resize мышью запрещён;
- handles на объекте не используются.

Режим `Show hitboxes`:
- выключен по умолчанию;
- показывает все hitbox-rect только как debug-режим;
- не является основным способом работы.

### 4.4. Hit-test и координаты

У каждого объекта есть вычисленный `pygame.Rect` в координатах игры.

Алгоритм:
1. Получить позицию мыши в координатах окна утилиты.
2. Проверить, находится ли мышь внутри preview viewport.
3. Перевести позицию мыши из preview-координат обратно в координаты `1600 x 900`.
4. Найти объект через `rect.collidepoint(...)`.
5. Для hover рисовать подсветку.
6. Для ЛКМ выбрать объект.

Все layout-дельты сохраняются в игровых пикселях, а не в preview-пикселях.

### 4.5. Навигатор объектов

Навигатор не является фильтром.

Назначение:
- показывать путь к выбранному объекту;
- объяснять, где объект находится в структуре экрана;
- позже поддержать полноценное дерево объектов.

Основной сценарий v2:
- пользователь выбирает объект в `PREVIEW AREA`;
- навигатор показывает путь от родителя к выбранному объекту.

Пример:

```text
game_table
`- players
   `- left
      `- panel
         |- portrait
         |- name_label <
         |- role_label
         `- loss_label
```

Позже навигатор может стать интерактивным деревом, но основной выбор в v2 происходит через preview.

### 4.6. Инспектор

Инспектор показывает и редактирует данные выбранного объекта.

Поля:
- `object_id`;
- `label`;
- `screen_id`;
- `module_path`;
- `object_type`;
- `x`;
- `y`;
- `width`;
- `height`;
- `delta_x`;
- `delta_y`;
- `width_delta`;
- `height_delta`.

Кнопки:
- `Dismiss`;
- `Cancel`;
- `Copy id`.

Семантика:
- `Dismiss` принимает изменения формы инспектора во временную RAM-сессию, обновляет preview, помечает объект как changed, но не пишет в `app_config.json`;
- `Cancel` откатывает изменения формы инспектора для текущего объекта к состоянию на момент выбора/начала редактирования;
- `Copy id` копирует идентификатор объекта в буфер обмена.

Инспектор никогда не пишет напрямую в `app_config.json`.

### 4.7. Управление объектом

Все изменения положения и размера выполняются только через блок `УПРАВЛЕНИЕ ОБЪЕКТОМ`.

Содержит:
- `Step`;
- кнопки движения: left/up/down/right;
- кнопки размера: `-W`, `+W`, `-H`, `+H`.

Клавиатура:
- стрелки дублируют кнопки Move;
- используется текущее значение `Step`.

`PREVIEW AREA` не поддерживает drag/resize мышью.

### 4.8. TO DO

`TO DO` — центральная навигационная система по задачам, а не просто текстовое поле.

Источник:
- RAM-сессия;
- после `Apply`: `app_config.json`;
- путь: `layout.<screen_id>.<object_id>.todo_text`.

Панель делится на две зоны:

1. `СПИСОК ЗАДАЧ`
   - показывает все объекты, у которых `todo_text` не пустой;
   - каждая запись содержит:
     - `screen_id`;
     - `object_id`;
     - `label`;
     - короткий preview задачи;
     - changed/unsaved marker.

2. `ЗАДАЧА ВЫБРАННОГО ОБЪЕКТА`
   - показывает текущий объект;
   - редактирует `todo_text`;
   - содержит кнопки:
     - `Save TO DO`;
     - `Clear TO DO`;
     - `Go to obj`;
     - `Copy task`.

Клик по задаче:
1. переключает экран;
2. выбирает связанный объект;
3. обновляет preview;
4. обновляет навигатор;
5. обновляет инспектор;
6. показывает текст задачи справа.

`Save TO DO` и `Clear TO DO` работают только с RAM-сессией.  
В файл пишет только глобальный `Apply`.

### 4.9. Copy task

`Copy task` копирует в буфер обмена структурированный текст для передачи в чат ИИ.

Это не JSON.

Формат:

```text
Layout task:
- screen_id: game_table
- object_id: player_left_panel
- label: Левая панель игрока
- object_type: player_panel
- module_path: durak_app.game_table
- rect: x=32, y=180, w=170, h=620
- deltas: dx=0, dy=0, dw=0, dh=0
- todo: Поднять панель выше и выровнять относительно верхней панели игрока.
```

Правила:
- если выбрана TO DO запись, копируется она;
- если TO DO запись не выбрана, копируется текущий выбранный объект;
- если `todo_text` пустой, поле `todo` всё равно присутствует.

## 5. Состояние и сохранение

Утилита работает с временной копией конфигурации в памяти.

Правила:
- любые изменения сначала живут только в RAM;
- `Dismiss`, управление объектом и `Save TO DO` меняют RAM-сессию;
- `Cancel` откатывает локальное редактирование выбранного объекта;
- `Reset session` откатывает всю RAM-сессию к состоянию запуска утилиты;
- `Apply` сохраняет всю RAM-сессию в `app_config.json`.

Сохранение:
- запись во временный файл;
- `os.replace(...)`;
- после записи показать понятный статус.

## 6. Источники данных

Источник объектов:
- экранные `layout_schema()`;
- связанные rect-вычисления экранов и GUI-слоя;
- `app_config.json`.

Модель остаётся `schema-first`.

Утилита не должна полагаться только на рекурсивный обход `pygame_gui`, потому что часть объектов находится в pygame-сцене.

## 7. Критерии готовности V2 shell

V2 shell считается готовым, если:

1. Интерфейс утилиты собран на `pygame_gui`.
2. Визуальный стиль отличим от игры и соответствует Windows 95-направлению.
3. Есть зоны:
   - верхнее меню;
   - выбор экрана/status/actions;
   - фильтр;
   - preview area;
   - навигатор;
   - инспектор;
   - управление объектом;
   - TO DO;
   - status bar.
4. `PREVIEW AREA` сохраняет 16:9 и работает как область hover/select.
5. Нет постоянного шумного overlay всех прямоугольников.
6. Все изменения положения/размера выполняются через control panel или клавиатурные стрелки.
7. `TO DO` работает как навигация по задачам.
8. `Copy task` формирует текстовый структурированный объект для чата.
9. Пользователю не нужно читать JSON для обычной работы.
