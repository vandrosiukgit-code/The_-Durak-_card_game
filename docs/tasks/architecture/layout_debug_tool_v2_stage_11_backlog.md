## Этап 11.1. Уточнить границы command router

Статус: закрыт, подтверждён пользователем после ручной проверки кнопок shell.

Цель: сделать `tools/layout_debug/commands.py` настоящим слоем маршрутизации команд, а не вынесенным куском shell.

Проблема:
- `LayoutDebugCommands.handle_button()` принимает `shell`;
- command router читает UI-поля shell;
- command router вызывает приватный `shell._current_step()`.

Сделать:
- заменить зависимость от `shell` на явную структуру с button refs и `current_step`;
- оставить фактические действия через callbacks;
- не менять поведение кнопок.

Критерий готовности:
- `commands.py` не обращается к приватным методам shell;
- зависимости command router видны по типам/параметрам;
- кнопки `Apply`, `Reset session`, `Copy`, `Add task`, `Clean`, `Dismiss`, `Cancel`, control buttons, filter buttons, `Show hitboxes` работают как раньше.

Проверка:
- `python -m unittest discover -s tests -p "test_*.py"`;
- ручной запуск `tools/layout_debug_tool_v2_shell.py`;
- пользователь проверяет основные кнопки.

## Этап 11.2. Вынести view-formatting из shell

Создать:

Сделать:

- покрыть formatter минимальными unit-тестами;
- shell должен только передавать state и устанавливать текст в виджет.

Критерий готовности:
- в shell нет ручной сборки HTML навигатора;
- в shell нет ручной сборки HTML выбранной задачи;
- формат отображения в UI не меняется.

Проверка:

## Этап 11.3. Изолировать clipboard adapter

Цель: clipboard должен быть отдельным IO-адаптером, а не частью shell.

Проблема:
- shell импортирует `pygame.scrap`;
- shell знает, как кодировать текст для clipboard на Windows;
- `TodoClipboardFormatter` уже отделён, но операция записи в буфер ещё в shell.

Создать:
- `ClipboardAdapter`;
- функцию или класс для `pygame.scrap`-записи.

Сделать:
- перенести `clipboard_text_bytes()` и `pygame.scrap`-операции в отдельный модуль;
- shell вызывает adapter и показывает статус операции;
- сохранить русский текст в clipboard.

Критерий готовности:
- shell не импортирует `pygame.scrap`;
- формат задачи остаётся структурированным текстом;
- при ошибке clipboard shell показывает понятный статус.

Проверка:
- `unittest` для кодирования/adapter без реального UI там, где возможно;
- ручная проверка `Copy`.

## Этап 11.4. Разделить event routing по зонам

Цель: `handle_event` должен быть верхнеуровневым маршрутизатором, а не местом знания всех UI-сценариев.

Проблема:
- `handle_event` обрабатывает pygame quit, keyboard, mouse hover/select, dropdown, text entry, selection list, buttons;
- дальнейшее развитие будет снова раздувать shell.

Сделать:
- выделить маленькие методы/роутеры по зонам:
  - preview mouse events;
  - context dropdown events;
  - inspector text entry events;
  - todo selection events;
  - button command events;
  - keyboard control events;
- оставить общий порядок обработки событий прежним.

Критерий готовности:
- `handle_event` читается как список маршрутов;
- каждый route имеет одну причину изменения;
- поведение hover/select, keyboard arrows, dropdown, inspector fields и buttons не меняется.

Проверка:
- `unittest`;
- ручная проверка основных сценариев UI.

## Этап 11.5. Убрать абсолютную геометрию из UI-панелей

  - navigator body;
  - inspector groups;
  - todo existing/new blocks;
- заменить группы магических чисел на именованные rect builders;
- не менять визуальный дизайн без отдельного решения пользователя.

Критерий готовности:
- ключевые rect строятся через именованные metrics;
- UI выглядит как раньше;
- будущая правка размера окна не требует охоты по десяткам чисел.

Проверка:
- ручной запуск;
- пользователь смотрит геометрию shell.

Критерий готовности:

- дальнейшая миграция к моделям понятна;
- тесты покрывают сохранение и откат.

Проверка:

## Принцип остановки

После каждого этапа:
