# Layout Debug Tool v2: архитектурный backlog

Статус: открыт, 2026-05-17.

Текущий этап: Этап 9 подтверждён пользователем, следующий этап — Этап 10 `Минимальные тесты чистых слоёв`.

Основан на:
- [../../architecture/code_quality_principles.md](../../architecture/code_quality_principles.md)
- [../../architecture/layout_debug_tool_v2_code_audit.md](../../architecture/layout_debug_tool_v2_code_audit.md)

Цель: привести код утилиты к базовым принципам надёжности, поддерживаемости и правильного разделения ответственности без потери уже подтверждённого поведения.

## Правило работы

Этот backlog не является разрешением на немедленный рефакторинг кода.

Код меняется только отдельными этапами после прямого указания пользователя. Каждый этап должен сохранять рабочий запуск `Layout Debug Tool v2`.

## Этап 0. Зафиксировать текущее поведение

Статус: закрыт документально.

Цель: перед рефакторингом описать, что нельзя сломать.

Baseline checklist:
- [layout_debug_tool_v2_baseline_checklist.md](layout_debug_tool_v2_baseline_checklist.md)

Проверяемые сценарии:
- запуск `tools/layout_debug_tool_v2_shell.py`;
- загрузка 4 экранов;
- переключение `game_table`, `main_menu`, `modal_intro`, `modal_endgame`;
- обновление навигатора при смене экрана;
- hover/select в `PREVIEW AREA`;
- обновление инспектора при выборе объекта;
- изменение `x/y/width/height` и deltas;
- движение кнопками;
- движение стрелками клавиатуры;
- `Dismiss`;
- `Cancel`;
- `Reset session`;
- `Apply`;
- создание задачи;
- отображение задачи в списке;
- копирование задачи в буфер обмена с русским текстом.

Результат:
- чеклист ручной проверки;
- решение, какие сценарии пользователь проверяет глазами.

## Этап 1. Вынести модели

Статус: закрыт, подтверждён пользователем после ручного запуска `tools/layout_debug_tool_v2_shell.py`.

Цель: отделить доменные данные от shell.

Создать:
- `LayoutObject`;
- `TodoTask`;
- `SelectionState`.

Правила:
- поведение UI не меняется;
- `LayoutObject` переносится без изменения смысла;
- сырые `dict` остаются только на границе config/session.

Критерий готовности:
- shell импортирует модели из отдельного модуля;
- запуск утилиты работает как раньше.

## Этап 2. Вынести config repository

Статус: закрыт, подтверждён пользователем после ручной проверки запуска и `Apply`.

Цель: изолировать чтение и запись `app_config.json`.

Создать:
- `LayoutConfigRepository`.

Ответственность:
- `load_config`;
- извлечение `layout`;
- сохранение layout;
- атомарная запись;
- сохранение остальных разделов конфига.

Критерий готовности:
- `_atomic_write_config` и `_apply_session_to_config` больше не находятся в shell;
- `Apply` работает как раньше;
- ошибки сохранения возвращаются как результат операции, а не прячутся в UI.

## Этап 3. Вынести RAM-сессию

Статус: закрыт, подтверждён пользователем после ручной проверки основных сценариев.

Цель: сделать изменения layout отдельной моделью состояния.

Создать:
- `LayoutSession`.

Ответственность:
- текущий layout;
- initial snapshot;
- dirty-state;
- selected object snapshot;
- update property;
- nudge object;
- dismiss selected object;
- cancel selected object;
- reset session.

Критерий готовности:
- shell не меняет layout-`dict` напрямую;
- inspector/control вызывают методы session;
- `Dismiss`, `Cancel`, `Reset session` работают как раньше.

## Этап 4. Вынести preview geometry

Статус: закрыт, подтверждён пользователем после ручной проверки preview, hover/select и hitboxes.

Цель: отделить игровую геометрию от shell UI.

Создать:
- `PreviewGeometryProvider`;
- screen adapters для `game_table`, `main_menu`, `modal_intro`, `modal_endgame`.

Ответственность:
- построить `dict[object_id, pygame.Rect]`;
- применить layout deltas;
- hit-test;
- canvas/viewport conversion.

Критерий готовности:
- shell не содержит `_game_table_preview_rects`, `_main_menu_preview_rects`, `_modal_intro_preview_rects`, `_modal_endgame_preview_rects`;
- hover/select работают как раньше.

## Этап 5. Вынести TO DO-логику

Статус: закрыт, подтверждён пользователем после ручной проверки TO DO.

Цель: подготовить задачи к дальнейшему развитию без разрастания shell.

Создать:
- `TodoService`;
- `TodoClipboardFormatter`.

Ответственность:
- собрать список задач из layout;
- выбрать задачу;
- создать задачу;
- подготовить текст для clipboard;
- позже редактировать существующую задачу.

Критерий готовности:
- shell не формирует структурированный текст задачи сам;
- `Add task`, `Clean`, список задач и `Copy` работают как раньше.

## Этап 6. Вынести shell layout metrics

Статус: закрыт, подтверждён пользователем после ручной проверки геометрии shell.

Цель: убрать разбросанные абсолютные числа из shell.

Создать:
- `ShellLayoutMetrics`;
- функции построения rect для зон:
  - context;
  - navigator;
  - inspector;
  - preview;
  - todo;
  - status bar.

Критерий готовности:
- основные `pygame.Rect` создаются через именованный layout object;
- внешний вид не меняется без отдельного решения пользователя.

## Этап 7. Разделить UI-панели

Статус: закрыт, подтверждён пользователем после ручной проверки shell.

Цель: уменьшить размер shell-класса и сделать UI-зоны самостоятельными.

Создать:
- `ContextPanel`;
- `NavigatorPanel`;
- `InspectorPanel`;
- `PreviewPanel`;
- `TodoPanel`;
- `StatusBar`.

Правило:
- панели строят виджеты и умеют обновляться из state;
- панели не сохраняют файл и не меняют layout напрямую.

Критерий готовности:
- shell собирает панели и передаёт им состояние;
- панели не знают лишнего о других панелях.

## Этап 8. Ввести команды действий

Статус: закрыт, подтверждён пользователем после ручной проверки кнопочных действий.

Цель: заменить длинный обработчик событий понятными командами.

Команды:
- `SelectScreen`;
- `SelectObject`;
- `UpdateInspectorProperty`;
- `NudgeObject`;
- `ResizeObject`;
- `AddTodoTask`;
- `CopyTodoTask`;
- `ApplySession`;
- `ResetSession`.

Критерий готовности:
- `handle_event` становится маршрутизатором;
- логика действий находится в command/session/service слоях.

## Этап 9. Удалить мёртвый код и честно обработать заглушки

Статус: закрыт, подтверждён пользователем после ручной проверки disabled-заглушек.

Цель: убрать шум и элементы, которые выглядят рабочими, но не работают.

Проверить:
- `hover_object`;
- `selected_object`;
- `_todo_list_html`;
- `Copy id`;
- `Edit`.

Решения:
- удалить;
- реализовать;
- disable;
- или явно отметить как будущую возможность.

Критерий готовности:
- в UI нет кнопок, которые выглядят рабочими, но ничего не делают без явного статуса.

## Этап 10. Минимальные тесты чистых слоёв

Цель: сделать будущий рефакторинг безопаснее.

Покрыть:
- `LayoutObject.from_config_entry`;
- загрузку layout;
- `LayoutSession` dirty-state;
- `Cancel`;
- `Reset session`;
- сохранение layout без потери других разделов config;
- формат `Copy task` с русским текстом.

Критерий готовности:
- тесты запускаются без открытия pygame-окна;
- тесты не требуют ручного клика.

## Принцип остановки

После каждого этапа:
- код должен запускаться;
- пользователь проверяет UI, если поведение видно глазами;
- коммит делается только после подтверждения или успешной проверки.

## Не делать в этом backlog

- Не менять визуальный дизайн без отдельного запроса.
- Не добавлять новые функции поверх старой архитектуры.
- Не переписывать всё одним большим коммитом.
- Не смешивать архитектурный рефакторинг с игровыми фичами.
