# Layout Debug Tool v2: baseline ручной проверки

Статус: baseline перед архитектурным рефакторингом, 2026-05-17.

Назначение: зафиксировать текущее пользовательское поведение, которое нельзя сломать при разбиении кода на слои.

Проверяется файл:
- `tools/layout_debug_tool_v2_shell.py`

## Правило проверки

После каждого архитектурного этапа утилита должна запускаться и проходить этот checklist без ухудшения подтверждённого поведения.

Если этап меняет только чистый слой без визуального эффекта, достаточно технической проверки запуска. Если меняется UI, preview, session, TODO или сохранение, нужна ручная проверка пользователем.

## 1. Запуск и загрузка

- [ ] Утилита запускается без падения.
- [ ] Окно помещается на экране пользователя `1680 x 1050`.
- [ ] Shell сохраняет стиль Windows 95/98.
- [ ] В строке состояния видно, что загружены 4 экрана.
- [ ] В строке состояния видно количество layout-объектов.

Ожидаемый смысл статуса:
- `Layout loaded: 4/4 screens`;
- `game_table`;
- `main_menu`;
- `modal_intro`;
- `modal_endgame`.

## 2. Переключение экранов

- [ ] `Игровой стол` открывается.
- [ ] `Главное меню` открывается.
- [ ] `Стартовая модалка` открывается.
- [ ] `Финальная модалка` открывается.
- [ ] При переключении экрана меняется список объектов в навигаторе.
- [ ] В строке состояния меняется текущая model-информация.

## 3. Навигатор объектов

- [ ] Навигатор показывает текущий экран.
- [ ] Навигатор показывает количество объектов текущего экрана.
- [ ] Навигатор показывает `Selected`.
- [ ] Навигатор показывает `Hover`.
- [ ] При hover в `PREVIEW AREA` обновляется `Hover`.
- [ ] При выборе ЛКМ обновляется `Selected`.
- [ ] Объекты с задачами помечаются как `TODO`.

## 4. Preview Area

- [ ] Preview сохраняет game canvas `1600 x 900`.
- [ ] Preview сохраняет aspect ratio `16:9`.
- [ ] Hover мышью подсвечивает объект.
- [ ] ЛКМ выбирает объект.
- [ ] Выбранный объект подсвечивается отдельно.
- [ ] Drag/resize мышью отсутствуют.
- [ ] `Show hitboxes` включает отображение всех hitbox-rect.
- [ ] `Show hitboxes` выключает отображение всех hitbox-rect.

## 5. Инспектор

- [ ] При выборе объекта обновляется `Object`.
- [ ] При выборе объекта обновляется `Type`.
- [ ] Поля `GEOMETRY` показывают текущие `x`, `y`, `width`, `height`.
- [ ] Поля `LAYOUT DELTAS` показывают `delta_x`, `delta_y`, `width_delta`, `height_delta`.
- [ ] Поля `VISUAL` показывают `color`, `font`, `font_size`.
- [ ] Изменение поля инспектора обновляет объект в RAM.
- [ ] После изменения появляется статус `UNSAVED`.

## 6. Control

- [ ] Поле `Step` задаёт шаг изменения.
- [ ] Кнопка `<-` двигает объект влево.
- [ ] Кнопка `->` двигает объект вправо.
- [ ] Кнопка `^` двигает объект вверх.
- [ ] Кнопка `v` двигает объект вниз.
- [ ] Кнопка `-W` уменьшает ширину.
- [ ] Кнопка `+W` увеличивает ширину.
- [ ] Кнопка `-H` уменьшает высоту.
- [ ] Кнопка `+H` увеличивает высоту.
- [ ] Стрелки клавиатуры дублируют движение объекта.
- [ ] После control-изменения появляется статус `UNSAVED`.

## 7. RAM-сессия

- [ ] Изменения не пишутся в `app_config.json` сразу после редактирования.
- [ ] `Dismiss` принимает текущее состояние выбранного объекта как локальную точку.
- [ ] `Cancel` откатывает выбранный объект к snapshot.
- [ ] `Reset session` откатывает всю RAM-сессию к состоянию запуска.
- [ ] После отката статус возвращается к `saved`, если layout совпадает с initial snapshot.

## 8. Apply

- [ ] `Apply` сохраняет RAM-layout в `app_config.json`.
- [ ] После `Apply` статус становится `saved`.
- [ ] После перезапуска утилиты применённые изменения остаются.
- [ ] Остальные разделы `app_config.json` не удаляются.
- [ ] Русский текст в JSON сохраняется читаемо.

## 9. TO DO: создание задачи

- [ ] Можно выбрать объект.
- [ ] Можно ввести текст новой задачи в поле `СОЗДАТЬ НОВУЮ ЗАДАЧУ`.
- [ ] `Add task` добавляет задачу выбранному объекту в RAM.
- [ ] После добавления задача появляется в списке созданных задач.
- [ ] После добавления объект помечается как `TODO` в навигаторе.
- [ ] `Clean` очищает поле создания новой задачи.

## 10. TO DO: просмотр и копирование

- [ ] Список созданных задач показывает задачи из `todo_text`.
- [ ] Можно выбрать задачу из списка.
- [ ] Выбранная задача отображается в просмотрщике.
- [ ] `Copy` копирует структурированный текст задачи в буфер обмена.
- [ ] Скопированный текст не является JSON.
- [ ] Русский текст в буфере обмена не превращается в mojibake.

Ожидаемый формат:

```text
Layout Debug Tool task
Screen: game_table
Object: bottom_hand_area
Path: game_table.bottom_hand_area
Type: hand_zone

Task:
Это тестовая задача!
```

## 11. Известные ограничения baseline

Эти пункты не считаются багом baseline, пока не начат отдельный этап:

- `Edit` для существующей задачи пока не реализован.
- `Copy id` пока не считается обязательным проверяемым сценарием.
- UX фокуса/курсора в многострочном поле создания задачи требует будущей полировки.
- Навигатор объектов пока текстовый список/дерево, не финальный tree-компонент.
- Preview показывает техническую rect-модель, а не полный визуальный слой игры.

## 12. Критерий прохождения baseline

Baseline считается пройденным, если:

- утилита запускается;
- пользователь может переключать экраны;
- hover/select работает;
- инспектор и control меняют выбранный объект;
- RAM-сессия, `Apply`, `Reset session`, `Cancel` сохраняют текущий смысл;
- можно создать задачу;
- можно скопировать задачу в чат с корректным русским текстом.
